# P7.7.3 workspace durable worker recovery

## Goal

Route every PostgreSQL worker job to the OpenCode Instance that owns its
SQLite-backed Session, and recover expired jobs after a process restart without
requiring another HTTP Prompt request.

## Contract

- `worker_job.workspace_directory` is persisted on enqueue.
- Legacy Prompt claims require an exact workspace partition.
- The server starts one recovery consumer for each explicitly allowlisted
  workspace.
- A recovery consumer loads the workspace through `InstanceStore.provide`, so
  Session, model, tool, permission, and event services receive the correct
  `InstanceRef`.
- PostgreSQL tenant RLS, generation, claim token, lease, and fencing checks
  remain authoritative.

## Configuration

```text
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_ENABLED=1
OPENCODE_POSTGRES_WORKER_QUEUE_WORKSPACES=/absolute/workspace/a,/absolute/workspace/b
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_RETRY_MS=1000
```

The recovery switch fails closed unless the SaaS legacy Prompt queue is also
enabled. Workspace paths must be absolute and are limited to 32 per process.

## Compatibility

The new column is nullable so existing P7.7.2 rows remain readable. A later
enqueue backfills the workspace for an existing Session job. Recovery consumers
ignore legacy rows without a workspace instead of guessing a SQLite Instance.

Session projection remains SQLite. This phase does not change the OpenCode agent
loop, tool execution, or model invocation path.
