# P7.3.5 Question shadow live acceptance

This gate validates the P7.3.4 Question shadow controls against real local
infrastructure. It does not create or install a system service.

## Gate topology

```text
8 Bun processes -> PostgreSQL shared breaker
OpenTelemetry SDK -> otelcol OTLP/HTTP receiver
otelcol Prometheus exporter -> Prometheus scrape
Prometheus HTTP query API -> breaker_open == 1
```

The PostgreSQL workload produces three command errors, three divergences, and
two matches in one eight-sample window. Both rates are `0.375`, above the
acceptance threshold of `0.25`.

## Run

Use official OpenTelemetry Collector and Prometheus binaries:

```bash
OPENCODE_QUESTION_SHADOW_LIVE_ACCEPTANCE=1 \
OPENCODE_QUESTION_SHADOW_BREAKER_DATABASE_URL=postgresql://... \
OPENCODE_P7_3_5_OTELCOL_BIN=/path/to/otelcol \
OPENCODE_P7_3_5_PROMETHEUS_BIN=/path/to/prometheus \
bun run --cwd packages/core test:question-shadow:live
```

The script:

- creates a unique breaker scope;
- launches eight independent Bun processes;
- checks shared breaker state after process restart;
- launches temporary Collector and Prometheus processes;
- exports the live breaker gauge over OTLP/HTTP;
- checks the Collector Prometheus exporter;
- checks Prometheus target health and query value;
- removes the breaker rows, temporary TSDB, configs, and child processes.

Successful output must include all eight checks and
`real-prometheus-breaker-query-equals-one`.
