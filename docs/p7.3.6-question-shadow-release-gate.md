# P7.3.6 Question shadow release gate

P7.3.6 converts the P7.3.5 live result into an HMAC-signed, build-bound and
environment-bound acceptance artifact. It keeps this gate separate from the
global PostgreSQL/SaaS startup proof until Question shadow rollout behavior has
production evidence.

## Promotion stages

| Current | Requested | Minimum samples | Minimum soak |
| --- | --- | ---: | ---: |
| 0% | 1% | 0 | 0 |
| 1% | 5% | 100 | 30 minutes |
| 5% | 25% | 500 | 2 hours |
| 25% | 100% | 2,000 | 6 hours |

Stages cannot be skipped. Error rate must remain at or below `5%`, divergence
rate at or below `10%`, readiness must be true, and the breaker must be closed.

An active stage returns `rollback` with recommended sample rate `0` when:

- telemetry is missing;
- readiness is false;
- the breaker is open;
- error or divergence rate exceeds its threshold.

## Sign live acceptance

```bash
OPENCODE_QUESTION_SHADOW_ACCEPTANCE_RESULT=/secure/p7.3.5-result.json \
OPENCODE_QUESTION_SHADOW_ACCEPTANCE_PROOF=/secure/p7.3.5-proof.json \
OPENCODE_QUESTION_SHADOW_ACCEPTANCE_KEY=secret-manager-value \
OPENCODE_RELEASE_ENV=production \
OPENCODE_BUILD_ID=git-sha \
bun run --cwd packages/core question-shadow:proof
```

## Evaluate promotion

```bash
OPENCODE_QUESTION_SHADOW_ACCEPTANCE_PROOF=/secure/p7.3.5-proof.json \
OPENCODE_QUESTION_SHADOW_ACCEPTANCE_KEY=secret-manager-value \
OPENCODE_RELEASE_ENV=production \
OPENCODE_BUILD_ID=git-sha \
OPENCODE_QUESTION_SHADOW_CURRENT_SAMPLE_RATE=0 \
OPENCODE_QUESTION_SHADOW_REQUESTED_SAMPLE_RATE=0.01 \
bun run --cwd packages/core question-shadow:release-gate
```

Exit code `0` means promote, `1` means hold, and `2` means rollback.

Load `docs/observability/question-shadow-alerts.yml` into Prometheus and route
alerts carrying `action=rollback` to the deployment controller. The gate emits
the recommended sample rate but intentionally does not mutate environment
variables or restart production services.
