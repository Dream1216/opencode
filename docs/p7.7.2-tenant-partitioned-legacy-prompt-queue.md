# P7.7.2 tenant-partitioned legacy Prompt queue

## Goal

Durably enqueue production legacy Prompt execution for explicitly allowlisted
SaaS tenants while SQLite remains the authoritative Session projection.

## Configuration

```sh
OPENCODE_DATABASE_BACKEND=sqlite
OPENCODE_SAAS_MODE=true
OPENCODE_POSTGRES_WORKER_COORDINATION_ENABLED=1
OPENCODE_POSTGRES_WORKER_COORDINATION_SAAS_SIDECAR=1
OPENCODE_POSTGRES_WORKER_COORDINATION_TENANTS=tenant_org_canary
OPENCODE_POSTGRES_WORKER_QUEUE_ENABLED=1
OPENCODE_POSTGRES_WORKER_QUEUE_SAAS_SIDECAR=1
OPENCODE_POSTGRES_WORKER_QUEUE_CONSUMER=legacy-prompt
OPENCODE_POSTGRES_WORKER_QUEUE_TENANTS=tenant_org_canary
```

## Runtime behavior

- Prompt recording remains synchronous and SQLite authoritative.
- The HTTP request enqueues one PostgreSQL generation and awaits completion.
- The legacy Prompt consumer polls only allowlisted tenants.
- The consumer reloads Session state, acquires the PostgreSQL execution lease,
  runs the existing Prompt loop, and completes the queue claim.
- A Session bound to an unlisted tenant receives generation `0` and follows the
  unchanged local execution path.
- The core V2 queue consumer is disabled in `legacy-prompt` mode.

## Acceptance

- Dynamic tenant Queue smoke passes enqueue, claim, heartbeat, completion, and
  unlisted-tenant bypass.
- A real Better Auth Prompt produces one completed queue generation and one
  completed execution lease.
- A stale claim cannot complete or fail a newer generation.
- Queue rows cannot be read through another tenant RLS context.
- Process kill and takeover increments both claim and fencing tokens.
- Session projection remains SQLite.
