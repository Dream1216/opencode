# P7.3.7 Question shadow production rollout

P7.3.7 connects the signed P7.3.6 gate to CI/CD and Secret Manager, deploys the
governed adapter at one percent, and requires a controlled production-host soak
before five-percent promotion can be evaluated.

## Secret sources

Release scripts accept direct values for local development or references:

- `env://NAME`
- `file:///mounted/secret`
- `aws-sm://region/secret-id#json-field`

CI should use `aws-sm://` with GitHub OIDC. A host without cloud identity may use
a root-readable `file://` mounted secret. Secrets must not be command arguments,
workflow inputs, systemd unit values, or repository files.

## CI/CD

`.github/workflows/question-shadow-rollout.yml`:

- validates release gate and Secret Manager tests;
- resolves proof, telemetry, and signing key references;
- blocks skipped stages and unhealthy windows;
- requires a separate GitHub Environment approval for apply;
- invokes the allowlisted remote rollout script over pinned-host SSH.

Required GitHub configuration:

- `OPENCODE_QUESTION_SHADOW_ACCEPTANCE_KEY_REF`
- `OPENCODE_DEPLOY_HOST`
- `OPENCODE_DEPLOY_USER`
- `OPENCODE_DEPLOY_SSH_KEY`
- `OPENCODE_DEPLOY_KNOWN_HOSTS`
- optional `AWS_DEPLOY_ROLE_ARN` and `AWS_REGION`

## One-percent soak

The production-host soak runs the real governed adapter and isolated
QuestionCommandGateway ask/reply comparisons. It does not create user Sessions
or send model requests.

```bash
OPENCODE_QUESTION_SHADOW_SOAK=1 \
OPENCODE_QUESTION_SHADOW_SOAK_OUTPUT=/secure/p7.3.7-telemetry.json \
bun run packages/opencode/script/question-shadow-rollout-soak.ts
```

Production defaults enforce:

- sample rate exactly `0.01`;
- PostgreSQL shared breaker;
- at least `100` comparison samples;
- at least `30` minutes elapsed;
- breaker closed;
- zero command errors and divergences for the controlled workload.

The five-percent gate remains `hold` until both the 100-sample and 30-minute
requirements are present in the signed telemetry evidence.
