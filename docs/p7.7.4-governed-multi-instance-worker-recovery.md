# P7.7.4 governed multi-instance worker recovery

## Goal

Expand P7.7.3 workspace recovery through deterministic tenant/workspace canary
partitions, expose cross-instance recovery outcomes, and stop unsafe recovery
automatically through a PostgreSQL-shared breaker.

## Runtime contract

- Recovery consumers are partitioned by exact `tenant_id + workspace_directory`.
- PostgreSQL claims include both tenant and workspace filters.
- Sampling is deterministic for a partition, so all instances agree whether a
  partition is inside the canary.
- Each admitted poll records `idle`, `completed`, or `failed`.
- Breaker samples persist the recovery instance ID, partition ID, and outcome so
  PostgreSQL evidence can attribute competing claims to concrete processes.
- Failures enter a shared breaker window. An open breaker pauses only the
  affected recovery partition; synchronous Prompt requests are unchanged.
- Workspace paths are represented in metrics by a 16-character SHA-256 digest.
- Session projection remains SQLite.

## Configuration

```text
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_SAMPLE_RATE=0.01
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_METRICS_SCOPE=p7.7.4-worker-recovery
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_BREAKER_BACKEND=postgres
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_BREAKER_DATABASE_URL=postgres://...
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_BREAKER_SCOPE=worker-recovery
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_BREAKER_WINDOW_SIZE=20
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_BREAKER_MIN_SAMPLES=5
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_BREAKER_ERROR_RATE=0.2
OPENCODE_POSTGRES_WORKER_QUEUE_RECOVERY_BREAKER_COOLDOWN_MS=60000
OPENCODE_WORKER_ID=opencode-web-1
```

The breaker URL falls back to `OPENCODE_DATABASE_URL`. Production must select
the PostgreSQL backend; memory mode exists for local tests only.

## Metrics

- `opencode_worker_queue_recovery_attempts_total`
- `opencode_worker_queue_recovery_selected`
- `opencode_worker_queue_recovery_breaker_open`
- `opencode_worker_queue_recovery_breaker_revision`
- `opencode_worker_queue_recovery_breaker_samples`

Metrics carry tenant, scope, workspace digest, and service instance labels.

## Acceptance gates

1. Two instances compete for the same tenant/workspace partition without
   duplicate completion.
2. Claim and fencing tokens remain monotonic through process termination.
3. A failure window opens one shared PostgreSQL breaker visible to both
   instances.
4. An open breaker stops background recovery but does not block the normal
   authenticated Prompt path.
5. Prometheus exposes both instance identities and shared breaker revision.
6. Session projection remains SQLite.
