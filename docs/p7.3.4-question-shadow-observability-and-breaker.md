# P7.3.4 Question shadow observability and breaker

P7.3.4 keeps the V1 Question/EventV2 path authoritative. The governed adapter
only decides whether the isolated P7.3.3 Command Gateway shadow comparison runs.
Sampling, telemetry, or breaker failures never change the primary response.

## Rollout

The global P7.3.3 switch remains off by default:

```bash
OPENCODE_EXPERIMENTAL_QUESTION_COMMAND_GATEWAY_SHADOW=true
OPENCODE_QUESTION_SHADOW_SAMPLE_RATE=0.01
```

Increase `OPENCODE_QUESTION_SHADOW_SAMPLE_RATE` through `0.01`, `0.05`, `0.25`,
and `1`. Sampling uses a stable SHA-256 bucket derived from `requestID`, so ask,
reply, reject, and restart seeding make the same admission decision.

## Automatic breaker

Defaults:

```bash
OPENCODE_QUESTION_SHADOW_BREAKER_BACKEND=memory
OPENCODE_QUESTION_SHADOW_BREAKER_WINDOW_SIZE=100
OPENCODE_QUESTION_SHADOW_BREAKER_MIN_SAMPLES=20
OPENCODE_QUESTION_SHADOW_BREAKER_ERROR_RATE=0.05
OPENCODE_QUESTION_SHADOW_BREAKER_DIVERGENCE_RATE=0.10
OPENCODE_QUESTION_SHADOW_BREAKER_COOLDOWN_MS=60000
```

The breaker opens when either rate is greater than its threshold after the
minimum sample count. During cooldown, further shadow commands are skipped.
The V1 Question path continues normally.

For a shared multi-instance breaker:

```bash
OPENCODE_QUESTION_SHADOW_BREAKER_BACKEND=postgres
OPENCODE_QUESTION_SHADOW_BREAKER_DATABASE_URL=postgresql://...
OPENCODE_QUESTION_SHADOW_BREAKER_SCOPE=tenant-production:question-command-gateway
```

The PostgreSQL implementation reuses the existing advisory-lock protected
shadow breaker tables and isolates Question state by scope.

## Metrics

OTLP metrics use the existing `OTEL_EXPORTER_OTLP_ENDPOINT`. Prometheus text is
appended to the existing authenticated `/experimental/worker-queue/metrics`
response.

- `opencode.question_shadow.decisions`
- `opencode.question_shadow.commands`
- `opencode.question_shadow.ready`
- `opencode.question_shadow.breaker_open`
- `opencode.question_shadow.sample_rate`
- `opencode.question_shadow.breaker_samples`
- `opencode.question_shadow.divergence_rate`
- `opencode.question_shadow.error_rate`

Do not advance a rollout while `ready=0`, `breaker_open=1`, or either rate is
above its configured threshold.
